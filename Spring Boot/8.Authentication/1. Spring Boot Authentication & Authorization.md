## 1. Authentication vs Authorization

### Authentication

**Authentication = Who are you?**

It verifies the identity of the user.

Example:

```text
username = dhanush
password = password123
```

Spring Security checks whether these credentials are valid.

If valid:

```text
User → Authenticated
```

---

### Authorization

**Authorization = What are you allowed to do?**

It checks whether an authenticated user has permission to access a resource.

Example:

```text
User:
    dhanush

Role:
    ROLE_USER
```

Endpoint:

```text
GET /admin/users
Required role: ROLE_ADMIN
```

Since the user only has `ROLE_USER`:

```text
403 Forbidden
```

# 2. HTTP Status Codes

|Status|Meaning|
|---|---|
|`200 OK`|Request successful|
|`201 Created`|Resource created|
|`400 Bad Request`|Invalid request|
|`401 Unauthorized`|User is not authenticated|
|`403 Forbidden`|User is authenticated but doesn't have permission|
|`404 Not Found`|Resource doesn't exist|

### Important

```text
401 → Authentication problem
403 → Authorization problem
```

# 5. SecurityFilterChain

The request first passes through Spring Security's filter chain.

```text
Client
   ↓
SecurityFilterChain
```

`SecurityFilterChain` contains the security configuration for the application.

Example:

```java
@Bean
SecurityFilterChain securityFilterChain(HttpSecurity http) {

    http
        .authorizeHttpRequests(auth -> auth
            .requestMatchers("/auth/**").permitAll()
            .requestMatchers("/admin/**").hasRole("ADMIN")
            .anyRequest().authenticated()
        );

    return http.build();
}
```

This tells Spring Security:

```text
/auth/**       → Public
/admin/**      → ADMIN only
Other APIs     → Authentication required
```

# 6. AuthenticationManager

`AuthenticationManager` is responsible for coordinating authentication.

Conceptually:

```text
AuthenticationManager
        |
        ↓
AuthenticationProvider
```

Example:

```java
Authentication authentication =
        authenticationManager.authenticate(
            new UsernamePasswordAuthenticationToken(
                username,
                password
            )
        );
```

The `AuthenticationManager` delegates the actual authentication work to an `AuthenticationProvider`.

---

# 7. AuthenticationProvider

The `AuthenticationProvider` performs the actual authentication.

For username/password authentication, Spring commonly uses:

```text
DaoAuthenticationProvider
```

Conceptually:

```text
AuthenticationManager
        ↓
AuthenticationProvider
        ↓
UserDetailsService
        ↓
Database
```

The provider:

1. Gets the username.
2. Loads the user.
3. Gets the stored password.
4. Uses `PasswordEncoder`.
5. Compares the passwords.
6. Creates an authenticated `Authentication` object if successful.

---

# 8. UserDetailsService

`UserDetailsService` is responsible for loading the user.

Example:

```java
@Service
public class CustomUserDetailsService
        implements UserDetailsService {

    @Override
    public UserDetails loadUserByUsername(String username) {

        User user = userRepository
                .findByUsername(username)
                .orElseThrow(() ->
                    new UsernameNotFoundException(
                        "User not found"
                    )
                );

        return User.builder()
                .username(user.getUsername())
                .password(user.getPassword())
                .roles(user.getRole())
                .build();
    }
}
```

The important flow is:

```text
Username
   ↓
UserDetailsService
   ↓
UserRepository
   ↓
Database
   ↓
UserDetails
```

# 10. PasswordEncoder

Passwords should **not** normally be stored as plain text.

Instead:

```text
password123
      ↓
PasswordEncoder
      ↓
$2a$10$................
```

Common encoder:

```java
BCryptPasswordEncoder
```

Example:

```java
@Bean
PasswordEncoder passwordEncoder() {
    return new BCryptPasswordEncoder();
}
```

During login:

```text
Client password
      ↓
PasswordEncoder
      ↓
Compare with stored password hash
```

If they match:

```text
Authentication SUCCESS
```

Otherwise:

```text
Authentication FAILED
```

After successful authentication, Spring Security creates an `Authentication` object.

Conceptually:

```text
Authentication
    |
    ├── Principal → dhanush
    ├── Authorities → ROLE_USER
    └── Authenticated → true
```

Example:

```text
Username:
    dhanush

Authorities:
    ROLE_USER

Authenticated:
    true
```

# 12. Generate JWT

In a stateless JWT application, after successful login, the application generates a JWT.

Example:

```text
Authentication successful
        ↓
Generate JWT
        ↓
Return JWT to client
```

Example response:

```json
{
    "token": "eyJhbGciOiJIUzI1NiJ9..."
}
```

The client then sends this token with future requests.

# 14. JWT Authentication Filter

A JWT filter checks the `Authorization` header.

Example:

```java
String header = request.getHeader("Authorization");

if (header != null && header.startsWith("Bearer ")) {

    String token = header.substring(7);

    // Validate token

    // Extract username

    // Create Authentication

    // Store authentication
    SecurityContextHolder
        .getContext()
        .setAuthentication(authentication);
}
```

The important header is:

```http
Authorization: Bearer <JWT>
```

# 15. SecurityContextHolder

After the JWT is successfully validated, Spring Security stores the authenticated user's information in:

```java
SecurityContextHolder
```

Conceptually:

```text
JWT
 ↓
JWT Filter
 ↓
Authentication
 ↓
SecurityContextHolder
```

The `SecurityContextHolder` allows the rest of Spring Security to know:

```text
Who is the current user?
What authorities does the user have?
Is the user authenticated?
```

# 16. Authorization

After authentication, Spring Security checks authorization.

Example configuration:

```java
.requestMatchers("/admin/**")
.hasRole("ADMIN")
```

Suppose the user has:

```text
ROLE_USER
```

Request:

```http
GET /admin/users
```

Spring Security checks:

```text
Is user authenticated?
        ↓
       YES
        ↓
Does user have ROLE_ADMIN?
        ↓
        NO
        ↓
403 Forbidden
```

# 26. Method-Level Authorization

Instead of configuring everything in the security filter chain, authorization can also be done at the method level.

Example:

```java
@PreAuthorize("hasRole('ADMIN')")
@GetMapping("/users")
public List<User> getUsers() {
    return userService.getUsers();
}
```

Another example:

```java
@PreAuthorize("hasAuthority('READ_USERS')")
public List<User> getUsers() {
    return userService.getUsers();
}
```

# 28. Stateless JWT Architecture

In a stateless JWT application:

```text
Client
   |
   | JWT
   ↓
Spring Boot
   |
   ↓
Validate JWT
   |
   ↓
Create Authentication
   |
   ↓
Process request
```

The server generally does not maintain a traditional HTTP session for the authentication state.

Configuration often includes:

```java
.sessionManagement(session ->
    session.sessionCreationPolicy(
        SessionCreationPolicy.STATELESS
    )
)
```

# 30. Interview Answer

### Question:

**Explain the authentication and authorization flow in Spring Security.**

### Answer:

> When a user logs in, the credentials are passed to the `AuthenticationManager`, which delegates authentication to an `AuthenticationProvider`. The provider uses `UserDetailsService` to load the user and `PasswordEncoder` to verify the password. If authentication succeeds, the application generates a JWT and returns it to the client.
> 
> For subsequent requests, the client sends the JWT in the `Authorization` header. A JWT filter extracts and validates the token and creates an `Authentication` object, which is stored in the `SecurityContextHolder`. Spring Security then performs authorization by checking the user's roles or authorities. If the user has sufficient permissions, the request reaches the controller; otherwise, Spring Security returns `403 Forbidden`.
